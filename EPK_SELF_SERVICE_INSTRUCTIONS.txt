HIGHLIFE EPK SELF-SERVICE HANDOFF
=================================

Every artist uses one permanent folder and one reusable visible Codex task.

Folder:
  /Users/dokworkmakk/Documents/Website Things HLL/EPK Generator Workspace/artists/<artist-slug>

Task title:
  EPK | <Artist Name>

For a new request:

1. Finish the request at /admin/epks and download the request plus every asset.
2. If artists/<artist-slug> does not exist, duplicate artists/_template and rename it to the exact slug shown by the website.
3. Put epk-build-request-<job-id>.txt directly in artists/<artist-slug>/input.
4. Put every downloaded supporting file in artists/<artist-slug>/input/assets without renaming it.
5. Create or restore the single task named EPK | <Artist Name>. Never create a second task for the same artist.
6. Send the exact command shown on the website completion screen.

After generation passes QA, the workspace finalizer automatically:

- moves the request to artists/<artist-slug>/archive/requests/<job-id>/;
- moves supporting files to artists/<artist-slug>/media while preserving filenames;
- safely deduplicates identical files and stops on different-content name collisions;
- updates ARTIST_EPK.md, CHANGELOG.md, QA_REPORT.md, and GENERATION_SUMMARY.md;
- leaves input ready for the next request.

The artist task may report:

  PASS — Ready for coordinator integration review.

only after that lifecycle is complete. A failed build leaves the request and assets in input. Generated code remains under artists/<artist-slug>/output for coordinator integration. This workflow never deploys production.
